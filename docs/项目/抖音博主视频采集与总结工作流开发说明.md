# 抖音博主视频采集与总结工作流开发说明

## 1. 当前开发状态

当前仓库已经完成第一期骨架开发，目标是先把 GitHub Actions 定时调度、状态去重、转写占位、结构化分析占位和日报输出跑通。

当前版本特点：

- 默认使用 `stub` 采集适配器生成示例视频数据
- 默认支持 `fetch / transcribe / analyze / report / all` 五种执行模式
- 使用 `outputs/state/processed.json` 保存去重状态
- 自动生成 Markdown 和 JSON 日报
- GitHub Actions 执行后会回写状态文件并上传产物

当前未完成部分：

- 真实抖音采集适配器
- 视频下载与音频抽取
- OCR、字幕识别等多模态输入
- 通知分发

## 3. 本地运行方式

### 3.1 安装依赖

```bash
pip install -r requirements.txt
```

### 3.2 执行完整流程

```bash
python -m app.main --mode all
```

### 3.3 单独执行某一阶段

```bash
python -m app.main --mode fetch
python -m app.main --mode transcribe
python -m app.main --mode analyze
python -m app.main --mode report
```

### 3.4 指定日期执行

```bash
python -m app.main --mode all --run-date 2026-06-26
```

## 4. 输出说明

执行完成后，主要输出位于：

- `outputs/raw/`：采集到的视频原始数据
- `outputs/transcripts/`：转写结果
- `outputs/analysis/`：结构化分析结果
- `outputs/reports/`：日报文件
- `outputs/logs/`：运行日志
- `outputs/state/processed.json`：去重状态文件

## 5. GitHub Actions 配置

工作流文件：

- `.github/workflows/douyin-daily.yml`

已支持：

- 每天定时执行
- 手动执行
- 执行完成后上传产物
- 自动提交状态文件

建议在仓库中配置以下 Secrets：

- `OPENAI_API_KEY`
- `DOUYIN_COOKIE`
- `DOUYIN_USER_AGENT`

建议配置以下 Variables：

- `OPENAI_TRANSCRIBE_MODEL`
- `OPENAI_ANALYSIS_MODEL`
- `PIPELINE_FORCE_MOCK_AI`

## 6. OpenAI 接入说明

当前实现逻辑如下：

- 如果设置了 `OPENAI_API_KEY`，并满足调用条件，程序会优先尝试真实 OpenAI 调用
- 如果没有密钥，或调用失败，会自动回退到本地占位逻辑

因此第一期重点是保证工程链路可运行，而不是直接依赖外部接口才能验证。
