# 抖音博主视频采集与总结工作流开发说明

## 1. 当前开发状态

当前仓库已经完成第一期骨架开发，目标是先把 GitHub Actions 定时调度、状态去重、转写占位、结构化分析占位和日报输出跑通。

当前版本特点：

- 默认使用 `stub` 采集适配器生成示例视频数据
- 新增 `local_seed` 适配器，可从本地 JSON 导入视频元数据
- 新增 `douyin_yt_dlp` 适配器，可直接尝试抓取抖音主页视频元数据
- 默认支持 `fetch / media / transcribe / analyze / report / all` 六种执行模式
- 使用 `code/douyin-workflow/outputs/state/processed.json` 保存去重状态
- 新增媒体准备阶段，可处理本地视频或远程媒体地址
- 自动生成 Markdown 和 JSON 日报
- GitHub Actions 执行后会回写状态文件并上传产物

当前未完成部分：

- OCR、字幕识别等多模态输入
- 通知分发

## 3. 本地运行方式

### 3.1 安装依赖

```bash
cd code/douyin-workflow
pip install -r requirements.txt
```

### 3.2 执行完整流程

```bash
cd code/douyin-workflow
python -m app.main --mode all
```

### 3.3 单独执行某一阶段

```bash
cd code/douyin-workflow
python -m app.main --mode fetch
python -m app.main --mode media
python -m app.main --mode transcribe
python -m app.main --mode analyze
python -m app.main --mode report
```

### 3.4 指定日期执行

```bash
cd code/douyin-workflow
python -m app.main --mode all --run-date 2026-06-26
```

## 4. 输出说明

执行完成后，主要输出位于：

- `code/douyin-workflow/outputs/raw/`：采集到的视频原始数据
- `code/douyin-workflow/outputs/media/`：下载的视频和抽取后的音频
- `code/douyin-workflow/outputs/transcripts/`：转写结果
- `code/douyin-workflow/outputs/analysis/`：结构化分析结果
- `code/douyin-workflow/outputs/reports/`：日报文件
- `code/douyin-workflow/outputs/logs/`：运行日志
- `code/douyin-workflow/outputs/state/processed.json`：去重状态文件

## 5. GitHub Actions 配置

工作流文件：

- `.github/workflows/douyin-daily.yml`

已支持：

- 每天定时执行
- 手动执行
- 执行完成后上传产物
- 自动提交状态文件

建议在仓库中配置以下 Secrets：

- `OPENAI_API_KEY`
- `DOUYIN_COOKIE`
- `DOUYIN_USER_AGENT`

建议配置以下 Variables：

- `OPENAI_TRANSCRIBE_MODEL`
- `OPENAI_ANALYSIS_MODEL`
- `PIPELINE_FORCE_MOCK_AI`

## 6. OpenAI 接入说明

当前实现逻辑如下：

- 如果设置了 `OPENAI_API_KEY`，并满足调用条件，程序会优先尝试真实 OpenAI 调用
- 如果没有密钥，或调用失败，会自动回退到本地占位逻辑

因此第一期重点是保证工程链路可运行，而不是直接依赖外部接口才能验证。

## 6.1 目录隔离说明

工作流代码已经迁移到 `code/douyin-workflow/`，这样不会和仓库中已有的页面文件、PPT 脚本或其他示例代码混在一起。

## 6.2 本地种子数据说明

如果还没有接真实抖音抓取器，可以先把视频元数据写到：

- `code/douyin-workflow/seeds/example_videos.json`

然后把 `config/creators.yaml` 中的 `fetch_adapter` 改成 `local_seed`。

单条种子数据支持的常用字段包括：

- `video_id`
- `title`
- `publish_time`
- `like_count`
- `comment_count`
- `share_count`
- `collect_count`
- `topic_tags`
- `transcript_hint`
- `media_url`
- `local_media_path`
- `audio_path`

说明：

- 如果有 `audio_path`，转写阶段会优先使用音频文件
- 如果有 `local_media_path` 或 `media_url`，媒体阶段会先准备视频并尝试抽取音频
- 如果暂时只有文本，可直接提供 `transcript_hint`

## 6.3 真实抖音采集说明

当前已经提供 `douyin_yt_dlp` 适配器，适合先验证“主页 -> 视频元数据”的真实抓取链路。

使用方式：

1. 在 `code/douyin-workflow/config/creators.yaml` 中把 `fetch_adapter` 改成 `douyin_yt_dlp`
2. 将博主主页地址写到 `homepage`
3. 根据实际情况配置以下任一登录态来源：
   - `DOUYIN_COOKIE`
   - `DOUYIN_COOKIE_FILE`
4. 执行：

```bash
cd code/douyin-workflow
python -m app.main --mode fetch
```

说明：

- `DOUYIN_COOKIE` 适合直接放到 GitHub Secrets
- `DOUYIN_COOKIE_FILE` 适合本地调试时引用 cookies 文件
- 当前适配器重点是拿视频元数据，不负责绕过平台限制
- 如果抓取失败，优先检查 Cookie、主页地址和站点结构变化
