## 目标与起点

目标：具备可以展示和解释的 AI 应用项目，开始有针对性地投递 Java 后端与 AI 应用结合的岗位，以及 Python AI 应用开发岗位。

已知起点：6 年 Java 开发经验，学过 Python 基础和一遍 LangChain。用户自评 Java 水平普通；独立项目能力尚未测评。

优先通过实践补齐模型调用、知识库检索、工具调用、流程控制、评估和部署，同时根据目标岗位补后端基础。

## 时间预估与使用方式

- 能独立完成知识库问答、工具调用并排查问题：可用约 3～4 周补工程细节、评估和面试。
- 跟课程做过，脱离教程仍需要大量参考：按约 6～8 周安排独立项目实践。
- 主要看过课程、实践较少：按约 8～12 周安排。
- 如果每天仅投入约两小时，可先按 2～3 个月规划，再根据实际进度调整。

以上是学习准备的规划估计，不是市场统计或获得录用的保证。求职耗时还取决于城市、薪资、岗位要求、面试表现与招聘进度。先完成能力检查，再调整周期。

## 起步能力检查

从空目录搭建一个 Python 服务，使用 FastAPI 提供接口，将一段售后描述交给模型，提取产品、问题和紧急程度三个字段。

完成要求：

- 返回结构化数据，校验必填项及字段取值。
- 记录调用耗时和错误，处理超时与模型返回格式错误。
- 服务能独立启动，提供调用示例。
- 可以查文档、使用 AI 辅助，但需要自己理解、修改和调试代码。

记录完成所需时间、参考来源和卡住的问题，用这些结果判断后续学习重点。

## 建议实践项目：售后工单助手

项目选择尚未确认。使用模拟订单和公开或自建产品资料，不使用原公司内部代码、资料和客户信息。

业务流程：

1. 接收客户描述，提取产品、问题和紧急程度。
2. 检索产品手册，生成带出处的回复草稿。
3. 调用受权限约束的接口查询模拟订单或设备状态。
4. 缺少必要信息时提出补充问题。
5. 经用户确认后创建工单，防止重复创建。
6. 记录执行过程、失败原因、耗时和调用费用。

建议先用 Python、FastAPI 和已学的 LangChain 开始，流程需要时引入 LangGraph。数据库按现有能力选择。需要展示 Java 经验时，可用 Java 提供订单与工单业务接口；先根据目标岗位确认是否值得增加这个服务。

## 学习重点

- Python：类型标注、异常、依赖管理、异步基础、服务开发和调试。
- 模型调用：上下文、结构化输出、流式响应、工具调用、超时、重试与费用。
- 知识库：解析、切分、向量检索、关键词检索、混合检索、重排、引用与权限过滤。
- Agent：工具参数、工作流与自主决策的区别、状态持久化、终止条件、失败恢复、人工确认。
- 工程与评估：数据库、日志、部署、权限、测试样本、任务成功情况、耗时与成本。

模型训练、大规模微调、推理优化和复杂多 Agent 系统先按目标岗位需要决定是否学习。
